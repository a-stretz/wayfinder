# Wayfinder User Guide

## Overview

Wayfinder is a prototype for turning operational signals into structured initiative thinking. It is not a task tracker. The goal is to clarify the problem, compare solution paths, and identify useful next actions.

## Home

Use Home as the strategic starting point.

- Review **Priority Recommendations** for initiatives that need attention.
- Use **Initiative Overview** to understand the shape of the portfolio.
- Scan **Emerging Patterns** to see repeated friction.
- Check **Recent Signals** for raw operational inputs.
- Review **Recommended Next Actions** to understand the current action mix.

## Initiatives

Use Initiatives to find and select work to inspect.

- Search by title or problem summary.
- Filter by department, recommended next action, or primary solution path.
- Select an initiative to open the detail workspace.
- Use the empty state as a cue to broaden filters.

## Initiative Detail

The Initiative Detail page is the main workspace.

- **Initiative Header:** Shows the title, department, and short problem summary.
- **Context Summary:** Explains the situation behind the initiative.
- **Inputs and Signals:** Shows the raw inputs that led to the initiative.
- **Scoping Analysis:** Frames the work before committing to a solution.
- **Recommended Path:** Shows the recommended next action and primary solution path.
- **Solution Options:** Compares possible solution paths using qualitative fit labels.
- **Candidate Requirements Map:** Groups possible requirements by category.
- **Requirements by Solution Path:** Shows how requirements change by path.
- **Target State and Future Scope:** Defines the intended future state and deferred work.
- **Pattern Learning:** Captures reusable learning from the initiative.

## Decision Priority

Use Decision Priority inside the detail workspace to test emphasis.

- Select one lens at a time.
- Review whether the recommendation changes.
- If the recommendation does not change, the page explains that only emphasis shifts.
- Review emphasis changes, affected paths, new questions, and future direction.

## Intake

Use Intake to simulate how raw input becomes structured initiative thinking.

- Enter a title, department, raw signal, optional tags, and optional notes.
- Select **Structure Signal** to generate a simulated draft.
- Review the suggested next action, primary solution path, and supporting paths.
- Select **Add to Initiatives** to add the draft to local state.

Local additions are not saved after refresh.

## Patterns

Use Patterns to see cross-initiative intelligence.

- Review repeated pain patterns.
- Look for common blockers.
- Check data readiness issues.
- See recurring systems, similar initiatives, and reusable requirement patterns.

Patterns help reveal where standard solutions or playbooks should exist.

## Playbook

Use Playbook to translate repeated patterns into action guidance.

- Review when each playbook should be used.
- Scan recommended first actions.
- Compare typical solution paths.
- Watch for common risks before moving too quickly.

## End-to-End Demo Flow

1. Start at Home and explain the control surface.
2. Open Initiatives and select an initiative.
3. Walk through the detail workspace from context to Recommended Path.
4. Apply a Decision Priority and show how emphasis changes.
5. Go to Intake and structure a new raw signal.
6. Add the draft to Initiatives.
7. Return to Patterns or Playbook to explain how repeated signals become reusable guidance.
